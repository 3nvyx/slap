# @slap/api

One Node process: the Hono REST API, `/ws/device`, `/ws/live/:lectureId`, and the built web app (`settings.webDist`, SPA fallback after `/api` and `/ws`). Session state is in memory (`src/sessions.ts`), so run exactly one instance (no cluster, no watch mode on demo day).

## Run

From the repo root:

- `pnpm --filter @slap/api dev`: watch mode on :8787. Env comes from `.env.local` at the repo root (or one level above it) (DATABASE_URL, DEEPGRAM_API_KEY).
- `pnpm --filter @slap/api start`: no reload. Use this for the demo.
- `pnpm --filter @slap/api typecheck`, then `pnpm --filter @slap/api test` (node:test; no network except the DATABASE_URL tests, which seed throwaway rows and delete them afterwards and are skipped without DATABASE_URL: `src/test/partner_loop.test.ts` (mock LLM and mock Fish), `src/test/devices.test.ts` (pairing, active class, device and web starts over the real routes and `/ws/device`, mock STT) and `src/test/classes.test.ts` (open class routes, per-caller study state, announcements, practice pick, ask, pretest, replay, vault export)). The database is shared, so these tests assert only on the rows they made.

Backends are chosen by env, read only in `src/settings.ts`: `STT_BACKEND=deepgram|mock`, `TRANSLATE_BACKEND=google|mock` (google needs GOOGLE_TRANSLATE_API_KEY), `DEVICE_KEYS` (comma list, default `dev-device-key`), `FISH_API_KEY` / `FISH_VOICE_ID` / `FISH_TTS_MODEL` (s2.1-pro) / `FISH_ASR_MODEL` (transcribe-1-pro) / `FISH_DIARIZE` (default on when a key is set) for the learning partner and diarization pass, `FISH_VOICES` (`id:Name:style,...`, up to 6 extra partner voices), `PUBLIC_URL` (encoded in the OLED join QR as `${PUBLIC_URL}/j/${classCode}`; keep it short so the QR fits in 64 px).

`GET /api/health` is liveness. `GET /api/health/ready` runs one `select 1` and reports `{ ok, mode, backends: { stt, translate, llm, db }, dbMs }`. It never calls a paid API. Call it before the demo to warm Neon. `/health` and `/health/ready` are aliases for container checks.

## Scripts

- `node src/scripts/fake_device.ts [file.wav] --url ws://localhost:8787/ws/device --key dev-device-key [--pair-code ABC123] [--seconds 60] [--show-oled]`: speaks the real device protocol: hello, wait for idle (or a resumed recording), button, real-time 3,200-byte PCM frames from the WAV, then a second button. `--show-oled` prints each frame as text. An unpaired device prints its pair code and waits for `POST /api/devices/pair`. `--no-start` stays idle until killed.
- `node --env-file-if-exists=../../.env.local --env-file-if-exists=../../../.env.local src/scripts/import_transcript.ts --class CS229 --title "Lecture 3" --date 2026-04-07 [--name NAME] [--dry-run] file.vtt|.txt`: uses the same import as the route. A class that does not exist is created.

## Modules

| File | Role |
|---|---|
| `server.ts` | Hono app, `upgrade` routing to the two ws servers, static files and SPA fallback, error JSON, `resumePendingJobs()` at start |
| `user.ts` | There is no sign-in. `withUser` sets `c.var.user.id` from the `X-Slap-User` header (an unverified per-browser id; `shared` when missing or malformed), which keys per-student state. `classOr404(classId)` is the only class check |
| `sessions.ts` | Registry of devices and lectures; `startSession`, `stopSession`, `pushAudio`, device pairing (`pairDevice`, `setActiveClass`, `unpairDevice`, `listDevices`, `deviceForWebStart`), snapshot logic, translation fan-out, segment persistence, transcript import and parsing |
| `ws/device.ts` | Device socket: key auth at upgrade (401), hello and pairing, buttons, audio, OLED frames, heartbeat |
| `ws/live.ts` | Caption socket: subscribe, snapshot, live events; same-origin check |
| `ws/audio.ts` | Browser-microphone fallback `/ws/lecture/:id/audio`: live lectures only, one audio source per lecture |
| `pipeline/stt.ts` | `createStt()`: raw-ws Deepgram nova-3, or a mock that replays `fixtures/lecture_sample.txt` paced by audio loudness |
| `pipeline/translate.ts` | `translate` and `translateMany` (Google v2 REST or mock `[xx] text`), LRU cache |
| `oled.ts` | 128x64 1-bit XBM frames via @napi-rs/canvas; QR from `qrcode` modules, EC level L, 2-module quiet zone |
| `routes/core.ts` | Public, Device and Signed-in endpoints of `docs/api.md`. Study routes are in `routes/study.ts`, learning partner routes in `routes/partner.ts`. All are relative to `/api` |
| `pipeline/fishAudio.ts` | Fish Audio over HTTP: `tts(text, { voiceId })` -> mp3 and `ttsStream(text, ...)` -> mp3 chunks as Fish sends them (latency low, 64 kbps), `asr(audio, { mime, diarize, language })` -> `{ text, segments, speakerTurns, duration, events }` with `<\|speaker:N\|>` markers and `[tags]` stripped; `PARTNER_VOICES`; WAV helpers. Mock mode without a key (or `setFishMock`): 1 s silent mp3, canned transcript |
| `pipeline/partner.ts` | Learning partner sessions (in memory, 60 min idle TTL), intent rules + LLM tiebreak, grading via `practice.grade`, reply assembly (lead clip <= 35 words + the next question spoken whole), streamed audio clips (`streamAudio`, `getClip`, `clipBytes`; random UUID ids, 10 min TTL, 100 MB cap) |
| `pipeline/diarize.ts` | Per-lecture PCM ring (6 min cap, memory only), Fish ASR `diarize=auto` every 5 min of audio and at stop, `mapSpeakers` onto `segments.speaker` |

## Behaviour the clients rely on

- **Device.** A known key is either a `devices` row or a key in `DEVICE_KEYS`; the row is created on the first hello. A device is paired when `ownerUserId` is set (the caller id that paired it; null = unpaired); paired devices are shared by every caller. It records into its active class (`classId`; null = none picked, the OLED says "Pick a course in the app" and a start is ignored and logged). A row with a `classId` but no owner (paired before owners existed) counts as paired; hello writes the class's creator as owner. Switching the active class (`POST /api/devices/:id/active-class`) re-sends `state` and the idle frame at once and is refused (409) while the device records another class; so is unpairing while recording. A web start uses a device pointed at that class, or switches a connected device that is not recording there first (`deviceForWebStart`; offline devices are never switched); a device only binds to a live lecture that has no browser microphone and no other device streaming. While unpaired, the `pairCode` from hello is stored and shown on the OLED. If it collides with a stale row, that row loses the code; with no code in hello, one is generated. A `state` message follows hello within about a second. OLED frames are sent on every change and re-sent every 3 s, because the firmware shows a server frame for only 5 s. Either button toggles start and stop, with a 1 s debounce; a slap that arrives before hello is processed is replayed afterwards. Audio is dropped unless the device is recording. If Deepgram stops draining audio, frames are dropped rather than queued. The server sends a JSON ping and a ws ping every 10 s and drops the socket after 30 s of silence.
- **Device drop mid-lecture.** The lecture stays live. Viewers get `status: "error"` and the STT stream is closed. When the device reconnects (hello), recording resumes into the same lecture with timestamps continuing. After a server restart, a `live` lecture up to 6 h old is resumed the same way.
- **Browser microphone.** `WS /ws/lecture/:id/audio`. The upgrade is always accepted so the page can read the close code: 4404 unknown lecture, 4410 not live, 4009 busy (a device or another browser is already streaming). Frames go to the same STT stream a device would use; one is created if needed. While a browser streams, a device that connects or presses start is not bound to the lecture. Stopping the lecture closes the browser socket with 1000.
- **Live captions.** After `subscribe {lang, since}` the client gets one `snapshot`, then live events. If no subscribe arrives within 1.5 s, the server sends a full snapshot anyway. `seq` is per lecture and only grows. It also grows across a server restart: it resumes from elapsed time × 100/s. A `since` from before the restart gets the full ring of the last 200 finals, so clients should dedupe finals by `segmentId`. Translations go only to viewers of that language. Each final is translated once per subscribed language (never interims) and persisted. The first viewer of a new language triggers a backfill of the last 20 finals. `status` (viewers, languages, median interim `latencyMs`) is sent on join and leave, on state changes, and every 10 s while live. `{type:"ping"}` is ignored.
- **Segment ids.** Ids are reserved in batches from the `segments` serial sequence, so a final is broadcast before its insert finishes. Inserts are chained in order. If the database is unreachable, captions keep flowing with negative ids and nothing is persisted.
- **Replay.** `POST /api/lectures/:id/replay` (`startReplay` → `startReplayFrom` in `sessions.ts`) plays a saved lecture's segments through a new ephemeral lecture of the same class (`persistent: false`, `replay` set): a timer emits interims (word prefixes from the stored word timestamps, or spread evenly without them) and finals at the original times scaled by `speed`, finals carry stored translations, `lectureState` reports `recording`, status events add `replay: true`, and the lecture stops itself after the last segment (`stopSession` clears the timer). One live lecture or replay per class; `/lectures/:id/public` and `/lectures/:id/stop` answer from memory for a replay id.
- **Stop.** Device state goes to idle at once. Deepgram is flushed (up to 4 s), pending writes finish, then the lecture is marked `processing` and `enqueueStudyBundle` is called. A lecture with no finals goes straight to `ended`.
- **Import.** WebVTT and SRT use their cue times; consecutive duplicate cues are dropped. Plain text is split into sentence-sized chunks of 6 to 40 words, timed at 2.5 words/s.
- **Learning partner.** `POST /api/classes/:classId/partner/session`: `lectureId` must belong to the class (404), `voiceId` must be in `GET /api/partner/voices` (400), `lang` is a language code (default `en`). The opening question is picked weak-concepts-first by `pickPractice`, preferring questions generated from `lectureId`. `POST /api/partner/:sessionId/turn` takes multipart `audio` (webm/opus, ogg, wav, mp3, or mp4/aac as Safari records it; type sniffed if missing; 415 otherwise) and/or `text` (JSON `{ text }` also works); an unknown or expired session is 404, audio over 10 MB or 60 s is 413 (WAV checked from the header, other formats after transcription), a Fish ASR failure is 502. Intent rules: a short utterance with skip/next/another (or "next question", "skip this", "give me another") asks a new question; one starting with explain / what is / what's / tell me about (optionally after "can you", "please", fillers) explains the named concept, matched against the class concept names, or the open question's concept for "that"/"this"; anything else answers the open question. Utterances the rules are unsure of go to `llm.complete` (task `partner_intent`) unless the LLM backend is mock. Reply fields: `intent` is `question` (skip / new question), `explanation`, `feedback` (graded answer; `grade` is set) or `chat` (nothing heard, no questions in the class, unknown concept). `questionId` is the question that is open after this reply (the next one for feedback), `conceptId` the concept the reply talks about. Feedback replies always end with the next question. Mcq answers are spoken as "B", "option c", "the second one" or the option's words and resolved before grading. Non-English sessions translate the transcript to English for intent and grading and the reply into the session language before TTS. Replies return before any audio is rendered: `feedbackAudioUrl` (short lead: acknowledgement, or grade + one line of explanation; null when there is none) and `audioUrl` (the next question, or the whole reply when there is no lead) are two Fish TTS streams started in parallel. Clients play `feedbackAudioUrl` first, then `audioUrl`. `GET /api/partner/audio/:id` waits for the first bytes and then streams chunked while Fish is still rendering; once a clip is finished it is served whole with Content-Length (replays). A clip whose TTS failed before any byte is 502. Spoken mcq questions read "stem? A: option. B: option. ..." with options cut at 15 words. The turn response carries `Server-Timing: asr, llm, translate, total` (TTS is not in it since it runs after the response).
- **Diarization pass.** Off unless `settings.fish.diarize` and a Fish key. `pushAudio` keeps a lecture-relative audio clock (STT offset + bytes sent) and feeds persisted lectures' frames into `pipeline/diarize.ts`. A pass waits ~3 s and for pending segment writes, then labels segments with at least half their duration inside the chunk; segments that fall in a gap between turns stay `null`. Speaker numbers are per chunk (0 = most talk time in that chunk; students are not tracked across chunks). After a pass, and whenever the study bundle saves the outline, student segments that read as questions are stored as `questionsAsked`; they live in the `outlines.announcements` jsonb as entries with `kind: "question"`, and `GET /api/lectures/:id` returns them split out as a top-level `questionsAsked: [{ segmentId, text, start }]` next to `announcements`.
- **Response shapes beyond contracts.** `GET /api/classes/:id` returns `device.state` as a `DeviceState` or `"offline"`, and `nextExam` as `{ name, date } | null` (earliest future exam in a syllabus). `ClassSummary.nextExam` is the date only. `POST /api/devices/pair` returns `{ deviceId, ownerUserId, activeClassId, connected, state }`; `GET /api/devices` and `POST /api/devices/:id/active-class` return `{ id, name, pairCode, activeClass: { id, name, code } | null, connected, state, lastSeenAt }` (`state` is `"offline"` when not connected). A duplicate class code is 409.
